## 1. 目标与范围

给平台补上「运行时可见性」三件套：

1. **Prometheus metrics**——HTTP 请求量/延迟/在途、作业队列深度，`/metrics` 抓取端点；
2. **结构化日志**——JSON 行格式可选项 + 全链路 `X-Request-Id`（API 与 worker 共用格式）；
3. **成本/延迟/错误面板**——项目级 JSON 聚合端点，把已有的 `usage_ledger_entries` /
   `event_logs` / `background_jobs` 数据变成一次请求可读的运行画像。

**明确收缩（记录取舍）**：

- **分布式 tracing（OTel）不做**。全套 OTel SDK 的接入成本远超当前收益，而
  `X-Request-Id` 已经给出「一条请求 → worker 处理的那条 job」的日志关联
  （事件日志里有 job_id / run_id / source_id）。需要跨服务 flame graph 时再立项。
- **指标不做客户端/SDK 埋点**。SDK 是零依赖外壳（T81 先例），可观测性只在服务端。
- **无新表、无 migration**。全部取数来自既有三张表，聚合在 Python 端做
  （沿用 `_dashboard_metrics` 的 Counter/sum 惯例——表都带索引，量级是单项目）。

## 2. 设计决策

### 2.1 `/metrics` 端点：main.py 直挂，绕开权限契约表

`/metrics` 的消费者是 Prometheus 抓取器，不是人也不是 API 调用方——它不该要
actor 身份，也不该进 OpenAPI（SDK generator 会为它生成无意义方法）。因此仿
HTML 页面先例（main.py `include_in_schema=False`、挂在 app 而非 `/api` router）：

- 不进 `POLICY` ∪ `OPEN_ENDPOINTS`，**三个契约计数不动**（若走 `/api/metrics`
  则要改 4 处钉值）；
- 不经过四个 app 级依赖（identity → permissions → idempotency 都不适用）；
- DB 侧 gauge 用 `Depends(get_store)` 取数，DB 异常时降级只出进程指标
  （抓取端点必须永远能吐文本，不能因 DB 抖动 500）。

### 2.2 指标集合（prometheus-client）

| 指标 | 类型 | 说明 |
|---|---|---|
| `s2v_http_requests_total` | Counter | `{method, path, status}`，path 用**路由模板**（`scope["route"].path`）防基数爆炸 |
| `s2v_http_request_duration_seconds` | Histogram | 同标签；`/metrics` 自身不计 |
| `s2v_http_requests_in_flight` | Gauge | 并发在途 |
| `s2v_background_jobs` | Gauge（抓取时算） | `{status}` 与 `{queue}` 两个维度系列 |
| `s2v_runs` | Gauge（抓取时算） | `{status}` |
| worker 侧 `s2v_worker_jobs_total` | Counter | `{outcome=processed/failed/retried/dead_lettered/reaped}` |
| worker 侧 `s2v_worker_job_duration_seconds` | Histogram | `process_background_job` 耗时 |

依赖：`prometheus-client>=0.21`（唯一新依赖；structlog 不引——stdlib logging
加一个 JSON Formatter 就够，避免双日志栈）。

### 2.3 结构化日志：stdlib + 可插拔 Formatter

- `apps/api/app/observability.py` 提供 `configure_logging(format, level)` 与
  `JsonFormatter`（一行一个 JSON 对象：`ts/level/logger/message` + record 上的
  结构化字段 + contextvar 里的 `request_id`）。
- API：uvicorn 之外的业务 logger 默认不配置（保持现状）；`LOG_FORMAT=json`
  时在 `create_app()` 里对 root logger 挂 JSON handler（幂等，防重复挂载）。
- Worker：`WORKER_LOG_FORMAT=json` 走同一个 Formatter（模块级共享，不留两份实现）。
- **Request-Id**：中间件优先采纳入站 `X-Request-Id`（上游 LB 已生成时透传），
  否则生成 `req_<hex12>`；写 contextvar、回响应头、进访问日志。

### 2.4 面板端点：项目作用域，复用既有权限键

`GET /api/projects/{project_id}/observability`，权限 `(Permission.PROJECT_READ,
SCOPE_PROJECT)`——与 dashboard 同款，**无新权限键（保持 18）**，嵌入钉定
（V7.4）天然可解析。响应 DTO `ProjectObservability`：

```jsonc
{
  "project_id": "...",
  "generated_at": "...",
  "cost":  { "estimated_total": ..., "actual_total": ...,
             "by_provider": {...}, "by_tool_key": {...}, "by_source_type": {...} },
  "latency": { "sample_count": n, "avg_ms": ..., "p50_ms": ..., "p95_ms": ... },
  "jobs":   { "by_status": {...}, "by_queue": {...},
              "dead_letter": n, "top_error_codes": {...} },
  "events": { "errors_by_type": {...}, "recent_errors": [ ...最新 10 条
              {event_type, message, created_at} ] }
}
```

取数口径：项目全部 run → `usage_ledger_entries` / `tool_invocations`（duration_ms）/
`background_jobs` / `event_logs(severity=error)`。均为既有表既有列，全时间窗
（不做窗口参数——面板先回答「这个项目整体健康吗」，按时间切片等有真实需求再说）。
