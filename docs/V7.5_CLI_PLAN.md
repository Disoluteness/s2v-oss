# V7.5 CLI 计划（T84）

## 1. 目标

路线图对 V7.5 的要求是一句话：「用于本地调试和服务器运维。支持创建 run、上传素材、查看 job、
下载成片。」这决定了 CLI 的两个边界：

- **它是 SDK 的外壳，不是第二条调用路径。** 鉴权、重试、幂等键、错误解码全部复用
  `Script2VideoClient`——SDK 修一个 bug，CLI 立刻受益，不存在两处漂移。
- **面向脚本与运维，不面向交互。** 输出支持 `--json`，退出码有明确约定，`runs wait`
  能在 shell 里当同步原语用；不做交互式向导，不做进度动画。

不做的事：不做 TUI；不做 provider 直连（CLI 只说 API 这门语言）；不做多配置文件
（一个 JSON 够运维用）；不引入任何运行时依赖。

## 2. 落地范围

### 2.1 住在 SDK 包里

CLI 代码是 `sdk/python/s2v/cli.py`，**不是**独立包或独立目录。理由：

- 复用零成本：同进程 import，不存在「CLI 自带一份 HTTP 逻辑」的平行实现；
- 分发零成本：`pip install s2v-client` 同时得到库与命令，`pyproject.toml` 加一行
  `[project.scripts] s2v = "s2v.cli:main"`；
- 版本零成本：CLI 与客户端同版本演进，命令参数跟着 API 走，不需要协调发布。

命令名是 `s2v`——与 SDK 导入名一致，避开产品名（本项目环境有别名重写怪癖，新目录/
文件名一律不用产品名；`s2v` 这个名字早已全库通用，是安全的）。

### 2.2 零依赖

`argparse`（stdlib）而不是 click/typer。SDK 的卖点是零运行时依赖，CLI 拖进
click 就把承诺破了——运维场景「pip 装一个包就能用」是这个取舍的回报。代价是
子命令树要手写，量在几百行以内，可接受。

### 2.3 配置解析

优先级：**命令行 flag > 环境变量 > 配置文件**，即「当场说的最算数」。

| 来源 | 键 |
| --- | --- |
| flag | `--base-url` / `--api-key` |
| 环境变量 | `S2V_BASE_URL` / `S2V_API_KEY` |
| 配置文件 | `~/.config/s2v/config.json`（键 `base_url` / `api_key`） |

- 配置文件目录用 `s2v`（import 名），不用产品名。
- 提供 `s2v config set base-url <url>` / `s2v config set api-key <key>` /
  `config show` / `config path`，写文件时 `0600` 权限（api-key 是明文落盘，
  与 `~/.netrc` 同级的安全假设；文档里写明）。
- 两者齐备才构造客户端；缺哪个报哪个，报错里带配置路径提示。

### 2.4 命令面

路线图点名的四件事都在，外加把它们串起来的支撑命令：

```text
s2v whoami                        当前身份（source / 席位 / 权限摘要）
s2v health                        健康检查
s2v config path|show|set K V      本地配置

s2v projects create TITLE [--description] [--language] [--aspect-ratio]
s2v projects list

s2v runs create PROJECT SCRIPT|--script-file F [--pipeline-key] [--brand-name]
        [--product-name] [--platform] [--duration] [--aspect-ratio] [--style-key]
        [--budget] [--quality-mode] [--idempotency-key]
s2v runs get RUN
s2v runs list --project P
s2v runs board RUN                run board 摘要（阶段 / 付费 provider / 成片）
s2v runs start RUN [--accept-intent-downgrade] [--accept-paid-providers]
s2v runs wait RUN [--timeout 600] [--poll-interval 3] [--no-stop-on-review]

s2v assets upload RUN PATH --type TYPE [--filename] [--mime]
s2v assets list --run RUN
s2v assets download ASSET -o FILE

s2v jobs list --run RUN
s2v jobs retry JOB
s2v jobs retry-failed --run RUN

s2v video get RUN                 成片元数据（asset_id / 下载链接）
s2v video download RUN -o FILE    下载成片（成片 = rendered_video / edited_video）

s2v review submit RUN DECISION [--note]      approve|reject|request_changes
s2v events --run RUN [--limit N]             事件流水（排障用）
s2v quick SCRIPT|--script-file F [--project P] [--download F]
                                             一站式：建 run → 启动 → 等待 → 成片
```

`quick` 包装 `client.script_to_video`：不指定项目就自动建项目。它是「脚本进、
成片出」的运维速记，也是 CLI 上最接近验收标准示例的入口。

### 2.5 输出与退出码

- 默认人类可读：单对象打键值对，列表打紧凑行（id + 状态 + 标题/名字）；
  `--json` 输出原始 JSON（模型的 `to_dict()`），字段不会因为 CLI 版本丢信息。
- 退出码约定（脚本化依赖这个）：

| 码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 其余失败（传输错误 / HTTP 错误 / 未知异常），stderr 打 `code: message` |
| 2 | 用法错误（argparse 默认） |
| 3 | `runs wait` / `quick` 等待超时（`RunWaitTimeout`） |
| 4 | `runs wait` / `quick` 等到的 run 以 `failed` 终态结束 |

- `waiting_review` 是**有意义的停点**而不是失败：`runs wait` 停在人关口返回 0，
  输出里带状态与 run id——人要介入的事不该被当成进程失败。
- `TransportError` 单独成支：连接不上时提示检查 base-url，而不是甩一个
  urllib 栈给用户。

### 2.6 明确不做的事

- **不做多配置/多租户 profile**：一个配置文件 + 环境变量覆盖已经覆盖运维场景，
  多 profile 是没有用户之前的设计。
- **不做交互式登录**：API key 由租户在 Web 端签发，CLI 只消费不签发
  （`apikey:manage` 是租户级权限，让 CLI 保管签发权会把密钥管理面扩大一圈）。
- **不做 provider 直连与本地渲染**：CLI 是 API 的客户端，不是平台本体。
- **不改服务端任何代码**：V7.5 无 migration、无新端点、无新权限键——
  纯客户端版本。现有 API 面已覆盖路线图点名的全部四件事。

## 3. 验证

- `tests/test_cli.py`：CLI 经 `AsgiTransport` 进程内打真实应用（与 SDK 测试同一
  harness），覆盖：
  - 配置解析优先级（flag > env > 文件）与缺配置的报错；
  - `whoami` / `projects create` / `runs create` / `runs get` / `runs list`；
  - `assets upload` → `assets download` 字节往返一致；
  - `jobs list` 与 `jobs retry` 的形状；
  - `video get` 的 `FinalVideoNotFound` → 退出码 1 且 stderr 有指引；
  - `runs wait`：完成 → 0、失败终态 → 4、人关口 → 0 且输出状态；
  - `--json` 输出是合法 JSON 且保留原始字段；
  - `ApiError` 的 stderr 形状为 `code: message`。
- `main(argv, client_factory=None)` 可注入客户端构造，测试不碰网络与真实配置文件。
- 全量 `pytest --basetemp=.pytest_tmp` 串行回归；`ruff check .` 收口。

## 4. 明确不做的事（重申）

无新表、无 migration、无新端点、无新权限键。门禁脚本**不**为 CLI 加节：
门禁只走 HTTP、跑在容器里的 API 进程上，而 CLI 属于客户端制品（与 SDK 同级），
由测试套件与文档示例背书——这与 T81 的先例一致（第 16 节验的是 SDK 所包装的
端点契约，不是 SDK 源码本身）。
