# V1.0 发布收口计划（T91）

状态：进行中（2026-10-12，T91）

路线图归属：V1.0 完整生产版 · 收官项（0.9.0 → **1.0.0**）

## 1. 目标与范围

V6 / V7 / V8 三个大版本已各自收口（最后一项是 V8.5 Deployment，T90）。路线图 §3 把「完整版本」
定义为一个**可嵌入内部平台的 Script-to-Video 服务**，§9 给出六条达标判据。本项不再新增能力，
而是把**已经能跑的系统**变成**可以对外承诺的系统**：

1. **版本冻结**——`APP_VERSION` 从 `0.9.0` 抬到 **`1.0.0`**。这不是仪式：`info.version` 是
   OpenAPI 文档里唯一对客户端作出的版本声明，留在 `0.9.x` 就等于告诉集成方「接口还会变」。
2. **变更记录**——新建 `CHANGELOG.md`，把 T00–T91 的交付按版本聚合。此前每次收口只在
   `docs/TASK_BOARD.md` 追加一行，**对外没有一份可读的历史**。
3. **API 稳定性与弃用政策**——新建 `docs/API_STABILITY.md` + `docs/DECISIONS.md` 的 ADR-006。
   1.0 的含义必须写下来才知道是什么含义：哪些面承诺稳定、哪些是实验面、改一个既有字段要走什么流程。
4. **示例项目**——新建 `examples/`：一条 SDK 之外的 curl 路径 + 一张三条路径的地图。
   路线图 V1.0 明确要求「有正式回归测试集和示例项目」；回归集已由 691 项 pytest + 门禁承担，
   而三条路径里**只有 curl 是空白**（两个 SDK 各自已有 `examples/`），所以只补那一条。
5. **发布回归清单**——新建 `docs/RELEASE_CHECKLIST.md`。`docs/DEPLOYMENT.md` 讲**怎么做**，
   本清单讲**发版前要确认什么**，两者不重叠。
6. **发布契约冻结**——门禁新增第 25 节，把「1.0 承诺什么」变成可重复执行的断言。

**明确不做（记录取舍）**：

- **不打 `v1.0.0` git tag**——项目不是 git 仓库（见记忆与 `docs/CURRENT_CONTEXT.md`），
  版本冻结落在 `version.py` 与 CHANGELOG，不引入一个不存在的版本控制步骤。
- **不做公开 marketplace / 多租户商业计费 / NLE 级时间线编辑器**——路线图 §4「V1.0 不要求」已列明。
- **不补 provider 主备的**新**实现**——只**验证**既有能力满足「≥3 类核心能力具备主备选择」；
  若环境里 provider 目录为空，门禁按**自适应**处理并打印（同第 23 节的理由：探测配置再断言，
  两个分支都打印，而不是把「本机没配 key」报成发布失败）。
- **不把示例做成端到端跑通出片**——示例的职责是演示**调用形状**。本机没有 provider key 时
  run 会停在 `waiting_review`，示例如实说明这一点，不伪造一条走完全程的记录。

## 2. 设计决策

### 2.1 版本号抬到 1.0.0，而不是 0.10.0

`APP_VERSION` 的 docstring 原文写着「V8 closes at `0.9.x`」——它描述的是**路线图进度**，而
1.0 描述的是**对外承诺**。两者在 V8.5 完成的那一刻对齐了：路线图 §9 的六条判据全部满足
（SDK 可建 run / 自动完成 preflight→发布包 / 失败可在 Web Studio 看到原因与修复动作 /
管理员可看 provider key 状态·用量·成本·失败率 / ≥4 类 pipeline / 部署升级备份回滚有文档）。
抬到 1.0 就是承认这件事，并把 `docs/API_STABILITY.md` 从「以后再说」变成「现在生效」。

**SDK 版本不与服务端版本绑定**：`s2v`（Python）与 `s2v-client`（TypeScript）各自带版本，
客户端版本不是关于服务端的陈述。1.0 冻结只落在服务端契约上，SDK 继续独立演进——这是
`version.py` 里已经写下的判断，本次不改。

### 2.2 契约冻结写在**测试**里，不只写在文档里

「承诺稳定」如果只在文档里，下一次改动不会有任何东西拦它。本项把承诺变成可执行的断言：

- `tests/test_release.py`——版本三处一致（`version.py` / OpenAPI `info.version` /
  `tests/` 里钉住的字符串）、制品存在、示例可解析、契约计数冻结；
- 门禁第 25 节——从**外部**（只走 HTTP）验证同一个契约，因为部署机上的契约是
  「这个镜像答出来的」，不是「仓库里写着的」。

两层的关系与 V7.1 的 `POLICY ∪ OPEN_ENDPOINTS == openapi` 契约测试一致：测试钉住**代码**，
门禁钉住**运行中的实例**。

### 2.3 只增不改：v1 契约的兼容规则

`docs/API_STABILITY.md` 把「稳定面」的改动分成三类，判据是**客户端会不会因此出错**：

| 改动 | 判定 | 理由 |
|---|---|---|
| 新增端点 / 新增响应字段 / 新增错误码 / 新增可选请求字段 | **允许**，不需公告 | 老客户端不会因此收到它不认识的**必填**输入 |
| 新增必填请求字段 / 删除响应字段 / 改既有字段类型或语义 / 收紧校验 | **不允许**，须先弃用 | 老客户端会静默失效（比报错更糟） |
| 改路由路径 / 改鉴权键 / 改错误码字符串 | **不允许**，须走弃用流程 | 同上，且会让幂等键与审计对齐失效 |

弃用流程（最短路径）：先**双跑**（新老字段/端点同时可用）→ 响应里带弃用标记 → CHANGELOG
记一条 → 至少跨一个**次版本**（1.x）才移除。这条流程刻意写得很短：本项目的「版本」是路线图
里的里程碑，不是每两周的迭代，一个需要跨两个里程碑才能删字段的流程等于永远不删。

### 2.4 实验面显式标注，而不是默认都算稳定

`/api/deployment` 与 `/metrics` 之外，还有一类面**故意不承诺**：`/api/provider-callbacks*`
（由上游供应商调用，形状跟着供应商走）、`/metrics`（运维面，标签集可能随观测需要调整）、
以及 `X-Embed-Token` 令牌的内部载荷（签名令牌的**内容是实现细节**，调用方只应把它当不透明串）。
把它们写进「实验面」清单不是为了降低质量，而是为了**避免把运维便利绑死成对外承诺**——
一个不能再改的指标标签集是负债。

### 2.5 示例只补「SDK 之外的那条路」，不复制已有的

两个 SDK **各自已经有 `examples/`**（`sdk/python/examples/` 两个、`sdk/typescript/examples/` 两个，
均带执行注释）。再在根目录复制一份意味着两份会各自腐坏的同样代码。所以 `examples/` 只放两样东西：

1. **`curl/run_pipeline.sh`**——一条 SDK 之外的路。它的价值不是「不用装包」，而是它是排查
   **集成问题**时的参照物：SDK 报错时，先用 curl 确认服务端答的是不是同一个形状，才能判断
   问题在 SDK 还是在服务端。此前仓库里没有任何 curl 示例。
2. **`README.md`**——一张地图，三条路径各自指向真正的文件，并说明同一套退出码约定
   （`0/1/2/3`，与 CLI 及两个 SDK 示例一致），因而都能直接进 CI。

`sdk/typescript/examples/` 与 `sdk/python/examples/` 是这两条路径的**正本**，不迁移、不复制。

## 3. 端到端影响

发布收口不改变任何运行时行为——除了 `info.version` 这一个字符串。逐项确认：

- **`info.version` 0.9.0 → 1.0.0**：影响 `GET /openapi.json` 与 `/docs`；`GET /api/deployment`
  的 `app_version` 跟随（同一常量）。SDK 不读版本号做分支，无兼容风险。
- **门禁节数**：新增第 25 节，总数随之变化，需同步 `docs/TASK_BOARD.md`、
  `docs/CURRENT_CONTEXT.md`、`docs/PLATFORM_PLAN.md`、`README.md` 四处总数与分解式。
- **新增文件不影响任何既有导入路径**：`CHANGELOG.md` / `docs/API_STABILITY.md` /
  `docs/RELEASE_CHECKLIST.md` / `examples/` / `tests/test_release.py` 全部是新增。
- **无 migration、无新表、无新依赖、无新环境变量**。表数仍 35（应用 34），依赖树不变。
