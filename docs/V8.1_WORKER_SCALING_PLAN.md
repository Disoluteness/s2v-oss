# V8.1 Worker Scaling 计划（T86）

状态：已完成（2026-10-10）
路线图归属：V8 规模化运行与企业治理版 · 第 1 项（0.9.x）

实测结果：`tests/test_worker_scaling.py` 19 项；全量 **536 passed, 1 skipped**；ruff 全绿；
migration `20261010_0018` 往返验证通过（列增删）；门禁新增第 20 节 10 项合计 **312 项**，
同一库连跑两次全绿。与计划的偏差只有一处：门禁第 20 节抓到 requeue 路由初版把「非 dead」
判断放在 store 返回之后（非 dead 原样返回 queued 通过了 `status == QUEUED` 检查直接 200），
已改为先查状态再调用 store。

## 1. 目标

让后台任务层支撑团队规模化使用：单 worker 实例安全扩到多实例、按角色拆分部署、
队列按优先级调度、失败有界自动重试、卡死任务有超时收割、重试耗尽进死信并可人工重放。

## 2. 现状与缺口（摸底结论）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 多实例 | claim 用 `SELECT ... FOR UPDATE SKIP LOCKED`，已安全 | 无角色拆分，所有实例干所有活 |
| 租约 | `locked_by` + `updated_at` 近似判断（伪租约） | 无显式 `lease_expires_at` |
| 优先级 | claim 纯 FIFO（`created_at`） | 无 `priority` |
| 重试 | 失败即 FAILED 终点，仅手动 `POST /jobs/{id}/retry` | 无自动重试、无退避 |
| 死信 | 无 | 重试耗无可追溯、无重放入口 |
| 超时 | 无任何 job timeout | 卡死任务只能靠租约被抢后重跑 |

现有 job 类型只有 `avatar_from_assets`（数字人提交/轮询）与 `stage_tool_step`
（capability：`media_analysis` / `subtitle_generation` / `video_composition` / storage 导出）。

## 3. 设计

### 3.1 队列（queue 列）与 worker 角色（role）

不加 `worker_queues` 新表——队列是 job 的属性不是独立实体（最小完备取舍），
`background_jobs` 加一列 `queue`（String(40)，NOT NULL，默认 `media`，索引）。

queue 由入队时的 job_type + capability 推导（`_queue_for_job`）：

| job_type | capability | queue |
|---|---|---|
| `avatar_from_assets` | — | `provider` |
| `stage_tool_step` | `media_analysis` | `analysis` |
| `stage_tool_step` | `subtitle_generation` | `media` |
| `stage_tool_step` | `video_composition` / storage 导出 | `render` |
| 其它 / 未知 | — | `media` |

worker 角色（`--role` / `WORKER_ROLE`，默认 `all`）→ 认领的队列：

- `all` → 全部四队列（默认，兼容现有单实例部署）
- `provider` → `["provider"]`
- `analysis` → `["analysis"]`
- `media` → `["media"]`
- `render` → `["render"]`

`planner` 角色本版不实现：规划目前是同步逻辑，没有 planner 类 job，建一个永远空转的队列
没有意义，留给后续任务化时再加。

manifest 派发（`dispatch_all_stage_execution_tasks`）所有角色都执行：它幂等
（`manifest_step_key` 去重），且是全局职责。webhook drain 与幂等键清理同理保留在所有角色。

### 3.2 优先级（priority 列）

`background_jobs` 加 `priority`（Integer，NOT NULL，默认 50，0–99，越小越优先）。
claim 排序改为 `priority ASC, created_at ASC`（FIFO 是优先级相同时的次序，不破坏旧行为）。

入队默认分层（便宜先跑、昂贵后置）：

- `media_analysis` → 40
- `subtitle_generation` / 未知 → 50
- `video_composition` / storage 导出 → 60
- `avatar_from_assets` → 50

`BackgroundJobCreate.priority` 可显式覆盖（ge=0 le=99）。

### 3.3 真租约（lease_expires_at 列）

`background_jobs` 加 `lease_expires_at`（DateTime，nullable）。claim 时设置
`now + lease_seconds`；可认领条件改为：

```
locked_by IS NULL OR locked_by = worker_id OR lease_expires_at IS NULL OR lease_expires_at < now
```

`lease_expires_at IS NULL` 让 migration 之前的旧行自然视为已过期可抢，不需要 backfill。
`updated_at` 近似判断**移除**——process 期间置 RUNNING / WAITING_PROVIDER / 进度更新处
显式续租（`update_job(lease_expires_at=...)`），语义显式。

### 3.4 job timeout（超时收割，不进程内中断）

`background_jobs` 加 `started_at`（DateTime，nullable）。`process_background_job` 把 job
置 RUNNING 时写 `started_at`。

worker 新增「收割」步骤（每轮执行，默认间隔 `WORKER_REAP_INTERVAL_SECONDS=60`）：
`store.reap_stalled_background_jobs(timeout_seconds)` 找 `status=running AND
started_at < now - WORKER_JOB_TIMEOUT_SECONDS`（默认 1800）的 job，逐个走
`_fail_background_job(error_code="job_timeout", ...)`。错误消息含 "timed out"，
被错误分类归为 NETWORK（retryable）——所以：

- `stage_tool_step` 超时 → 自动重试（见 3.5）
- `avatar_from_assets` 超时 → failed 终点（见 3.5 的付费安全取舍）

**WAITING_PROVIDER 不受 timeout 影响**（数字人轮询可持续数小时，那是租约的事）；
进程内不做信号中断——同步执行体是 ffmpeg 子进程/provider HTTP，DB 侧收割 + 有界重试
比杀线程可靠且可移植。

### 3.5 自动重试 + 指数退避 + 死信（dlq）

`_fail_background_job` 升级为「失败处置器」，按错误分类（`classify_error`，已有
`error_retryable` 语义：provider/quota/network 可重试，auth/input/runtime/quality/
cancelled/unknown 不可）与 job 类型分流：

1. **可重试错误 且 job_type == `stage_tool_step` 且 attempt < max_attempts**
   → 自动重新入队：`status=queued`、`attempt += 1`、`next_run_at = now + backoff`、
   清租约、保留错误字段（board 可解释这次失败）、事件 `job.retry_scheduled`（warning）。
   `backoff = min(base * 2**(attempt-1), cap)`，base=`WORKER_RETRY_BACKOFF_BASE_SECONDS`
   （默认 30）、cap=`WORKER_RETRY_BACKOFF_CAP_SECONDS`（默认 3600）。
2. **可重试错误 且重试耗尽** → **死信**：新状态 `dead`（`BackgroundJobStatus.DEAD`），
   事件 `job.dead_lettered`（ERROR）。
3. **不可重试错误**（含全部 RunGateError 闸门失败——实测闸门 code 均落非可重试分类）
   → 维持现状 `failed` 终点 + `job.failed` 事件。
4. **`avatar_from_assets` 一律不自动重试**（`allow_auto_retry=False`）：数字人提交是
   付费 provider 调用，自动重试 = 无人值守重复计费风险；保持「失败即终点 + 手动 retry」。

`next_run_at` 列（DateTime，nullable）：claim 过滤 `next_run_at IS NULL OR next_run_at <= now`
——退避中的任务不领。`retry_job`（手动）清 `next_run_at`。

### 3.6 死信重放端点

`POST /api/jobs/{job_id}/requeue`：仅 `dead` 状态可重放 → `queued`、`attempt=1`
（fresh，参照 webhook `requeue` 的语义）、清错误与 `next_run_at`、事件 `job.requeued`。
非 dead → 409 `conflict`；未知 job → 404。
POLICY 新增一行（`RUN_WRITE` + `SCOPE_JOB`），复用既有权限键，**不新增权限键**。

### 3.7 DTO 与契约

- `BackgroundJobStatus` 增 `DEAD = "dead"`（事件词汇表不受影响——`job.dead_lettered`/
  `job.retry_scheduled`/`job.requeued` 是内部事件，不在 `WEBHOOK_EVENT_SOURCES` 六事件内）。
- `BackgroundJob` DTO 增 `queue` / `priority` / `started_at` / `lease_expires_at` / `next_run_at`。
- `BackgroundJobCreate` 增 `priority`。
- 新端点 1 个：受控 path 110→**111**、operation 139→**140**、受控 118→**119**。
  错误码不新增（requeue 冲突用 `conflict`），权限键不新增。

### 3.8 migration `20261010_0018_worker_scaling`

`background_jobs` 加 5 列（queue/priority 带非空 server_default，旧行自动落默认）+
`queue` 索引；并对 `job_type='avatar_from_assets'` 的旧行 backfill `queue='provider'`
（`stage_tool_step` 旧行留默认 `media`——capability 在 JSON 里跨 MySQL/SQLite 不可移植地
解析，且旧行多为终态不被 claim，偏差可接受，文档注明）。表数不变（32），head 0017→**0018**。
往返验证 upgrade→downgrade→upgrade。

## 4. worker 进程参数（新增）

| 参数 / 环境变量 | 默认 | 说明 |
|---|---|---|
| `--role` / `WORKER_ROLE` | `all` | 认领的队列集 |
| `--job-timeout-seconds` / `WORKER_JOB_TIMEOUT_SECONDS` | 1800 | RUNNING 超时阈值 |
| `--reap-interval` / `WORKER_REAP_INTERVAL_SECONDS` | 60 | 收割扫描限频 |
| `--retry-backoff-base` / `WORKER_RETRY_BACKOFF_BASE_SECONDS` | 30 | 退避基数 |
| `--retry-backoff-cap` / `WORKER_RETRY_BACKOFF_CAP_SECONDS` | 3600 | 退避上限 |

worker 退避参数需要传到 store 层（`BackgroundJobWorker` 构造时把
`retry_backoff_base_seconds` / `retry_backoff_cap_seconds` 传给 store 的失败处置）。
部署侧 `.env.example` 补 worker 条目；**部署需重建 api + worker 两个镜像**（db_store 与
worker 都改了）。

可重试失败自动重试（queued + attempt+1 + next_run_at + `job.retry_scheduled`）、

avatar 终点、WAITING_PROVIDER 不收）。

## 6. 不做的事（本版边界）

- 不建 `worker_queues` 表（队列是列不是表）。
- 不做 planner 角色（无对应 job 类型）。
- 不做进程内执行超时（DB 收割替代）。
- 不做 job 取消/暂停 API（现有 state action 已有取消路径）。
- 不做每 job 独立 timeout 配置（全局阈值）。
