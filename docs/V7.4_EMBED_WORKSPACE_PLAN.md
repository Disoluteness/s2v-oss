# V7.4 Embeddable Workspace — 设计与落地记录

状态：**进行中（T83）**。前置：V6.5 请求身份 / 权限矩阵（§V6.5）、V7.1 错误信封、V7.2 API key 身份、V7.3 事件词汇表。

## 1. 目标与验收

路线图 V7 第 4 项：让内部平台把 Studio **嵌进自己的界面**——外部系统只需给出
`project + run + 上下文`，它的终端用户无需在本平台登录即可打开、查看、审核这个 run。

验收标准：

1. 外部平台可以用自己的 API key 调一次接口，拿到一个**短时效、可撤销（靠过期）的嵌入链接**。
2. 链接在 iframe 与浏览器直开两种形态下都可用；被嵌页面**只暴露被钉定的那个 run**，
   改 URL 里的 id 拿不到别的 run。
3. 嵌入身份**不是**平台席位：它拿不到租户级端点（团队、webhook、api key、集成管理），
   也拿不到席位权限——授权**只**来自令牌自身携带、且被上限白名单约束的 scope 集。
4. 被嵌页面只能出现在**已登记**的外部来源（`allowed_origins`）里，通过 CSP
   `frame-ancestors` 表达，而不是靠前端自觉。
5. 令牌泄漏的爆炸半径有界：默认 15 分钟、上限 24 小时；仅签名不加密，因此不放任何秘密。

## 2. 为什么是「平台签发」而不是「平台验签」

两条路可选：

- **A（选它）平台签发**：外部平台用 API key 调
  `POST /api/external-integrations/{id}/embed-sessions`，平台返回 `token + embed_url`。
- B 外部自签：平台下发一个共享密钥，外部平台自己造令牌，我们只验签。

B 需要外部平台保管一个能签发「在本平台可读数据」的凭证，且签名逻辑要在每个宿主侧复刻
一遍（多语言、易错）。A 把密钥留在我们这一侧——**外部平台永远不持有签名密钥**，它只需要
自己的 API key。代价是每次开嵌入页要一次网络往返，这在服务端 → 服务端调用里不是问题。

令牌因此是**无状态的**：没有 `embed_sessions` 表，没有后台清理任务。撤销 = 撤销集成
（`status=disabled`，校验时查一次集成）或等它过期。集成状态是唯一需要在验签时读库的字段。

## 3. 令牌格式与签名

```
s2v_embed_<base64url(payload_json)>.<hex hmac_sha256(secret, base64url_payload)>
```

前缀 `s2v_embed_` 与 API key 的 `s2v_` 不同，解析上**毫无歧义**（先看更长的前缀），
也让「这是嵌入会话」在日志里一眼可辨。

payload（短键，URL 里要短）：

| 键 | 含义 |
| --- | --- |
| `v` | 格式版本，当前 `1` |
| `iid` | 集成 id（校验时查状态与 allowed_origins） |
| `tid` | 租户 id |
| `sub` | 外部系统里的终端用户 id（**这是身份，不是权限**） |
| `nam` | 显示名（可选） |
| `pid` | 钉定的 project_id（必须） |
| `rid` | 钉定的 run_id（可选；给了就同时钉 run） |
| `pg` | 打开哪一页：`workspace` / `run-board` |
| `scp` | 授权 scope 集（`EMBED_ALLOWED_SCOPES` 的子集） |
| `exp` | 过期时刻（unix 秒） |
| `jti` | 随机 id，仅用于日志/审计关联 |

签名密钥是部署级 `EMBED_TOKEN_SECRET`（与 `API_KEY_PEPPER` 同性质的破坏性配置：
改它会让所有在途嵌入链接立即失效）。**签名不是加密**：payload 明文可读（base64url 不是
保密手段），所以不放任何秘密——放的都是调用方本来就持有的 id。

`exp` 在签名串内，改过期时间会破坏签名；校验只看 `exp`，不设容差窗口（嵌入链接是人手
点开的，不像 webhook 有投递延迟）。

## 4. 授权模型：令牌是第二个授权来源

现有链路是「身份 → 席位（团队角色 ∪ 项目角色）→ 权限」。嵌入会话**没有席位**：
它代表外部系统的终端用户，我们这边没有 `team_memberships` 行，`actor_seat` 返回
`None`，按席位判定会得到「空权限、全拒」。

所以 `require_permission` 增加**第二个授权来源**：

```python
if grant_scopes is not None:                 # 嵌入会话
    allowed = permission.value in grant_scopes and permission in EMBED_ALLOWED_PERMISSIONS
    reason = "embed_scope"
else:                                        # 席位（原有路径）
    allowed = seat_allows and not out_of_scope
    reason = "api_key_scope" if out_of_scope else "seat"
```

两层上限，缺一不可：

1. **签发时**：请求的 scope 必须是 `EMBED_ALLOWED_SCOPES` 的子集，越界直接 400；
2. **请求时**：`permission in EMBED_ALLOWED_PERMISSIONS` 再判一次——这样即使令牌是用旧
   版本代码签发的（当时白名单更宽），收紧白名单后也立即生效，不需要等令牌过期。

```python
EMBED_DEFAULT_SCOPES = {project:read, run:read, asset:read, library:read}
EMBED_ALLOWED_SCOPES = EMBED_DEFAULT_SCOPES | {run:review}     # 显式 opt-in
```

`run:review` 是唯一可选的写权限，因为「审核」正是嵌入形态最有力的用例（V7.3 的
`stage.waiting_review` webhook → 外部平台弹出嵌入页 → 人在外部门户里点通过）。
`run:write` / `run:start` 一律不给：它们能触发付费 provider 调用，把花钱的能力塞进一个
会出现在第三方页面里的链接，不是默认该有的授权。

## 5. 上下文钉定（context pinning）

令牌是给**浏览器**的，浏览器里的东西可被终端用户随意修改，所以「只暴露钉定的 run」
必须由服务端强制。规则（全部在 `permission_policy.enforce_api_permissions` 里一处实现）：

1. **租户级端点一律拒绝**（`SCOPE_TENANT`）：`GET /api/projects` 这类端点按定义跨项目，
   钉定无从谈起。拒绝理由 `embed_context`。
2. **目标项目必须等于 `pid`**：用既有的 `_resolve_project_id` 解出该请求真正要碰的
   project，与令牌比对，不等即拒。
3. **给了 `rid` 就再钉一层**：run 级请求的 `run_id` 必须等于 `rid`。

三条都走同一个拒绝路径：`PermissionDenied(..., reason="embed_context")` → 403 审计留痕。
钉定检查放在权限判定**之前**：先确认「这个请求是否在令牌的作用域内」，再谈「有没有权限」。

## 6. 数据模型（migration `20261010_0016_external_integrations`）

```text
external_integrations
  id            str  pk          "extint_xxxxxxxxxxxx"
  tenant_id     str  index
  name          str(160)
  slug          str(64)  unique(tenant_id, slug)
  description   text   null
  allowed_origins json           # ["https://portal.example.com"]，CSP frame-ancestors 用
  status        str(16)          # active | disabled
  created_by    str(64) null
  created_at / updated_at
```

只有一张表：**集成是登记，令牌是无状态的**。`allowed_origins` 是「允许谁把我嵌进页面」
的白名单，在 `/embed` 页面响应时变成 `Content-Security-Policy: frame-ancestors ...`。
删集成时**不**级联删任何东西（没有引用它的行）；在途令牌因查不到集成而立即失效。

## 7. 端点与页面

受控端点（`POLICY`，全部需要第 18 个权限键 `integration:manage`，租户级）：

| 方法 | 路径 |
| --- | --- |
| POST | `/api/external-integrations` |
| GET | `/api/external-integrations`（`Page` 信封） |
| GET | `/api/external-integrations/{integration_id}` |
| PATCH | `/api/external-integrations/{integration_id}` |
| DELETE | `/api/external-integrations/{integration_id}` |
| POST | `/api/external-integrations/{integration_id}/embed-sessions` |

开放端点（`OPEN_ENDPOINTS`）：

- `GET /api/embed/{integration_id}/session` —— **令牌自描述**：请求头带
  `X-Embed-Token: s2v_embed_...`，返回 `{actor_id, display_name, source, integration_id,
  integration_name, context:{project_id, run_id, page}, scopes, expires_at,
  remaining_seconds}`。它必须开放（身份自举，同 `/api/me`），且因身份解析是应用级依赖，
  令牌错了就是 401 而不是 200。**故意不给** `permissions` / `team_role` / `seat` 字段：
  嵌入会话没有席位，回一个空集合只会诱导调用方把它当 `/api/me` 用。

  两个实现细节与最初的草案不同，都以实现为准：

  1. **专用请求头而非 Bearer**。`Authorization: Bearer` 归 V7.2 的 API key 层所有，
     任何它不认识的 Bearer 都会得到 401 `api_key_invalid`。共用同一个头会让「你的嵌入
     链接过期了」与「你的 API key 写错了」塌成同一个无法区分的 401。因此嵌入令牌走
     `X-Embed-Token`；不带该头的请求行为零变化。
  2. **集成 id 在路径里**，与页面路径同构。首个文档请求不带任何凭据（令牌在 fragment，
     浏览器不会发送），没有 id 就算不出 `frame-ancestors`。路径里的 id 与令牌内的 id
     **必须一致**，否则 401：A 集成的宿主被允许分帧我们的页面，却拿到 B 集成的钉定 run，
     是一条无需篡改签名就能越过的嵌入边界。

HTML 页面（`include_in_schema=False`，**不进** `/api` 路由，因此不受策略表管辖）：

- `GET /embed/{integration_id}`、`GET /embed/{integration_id}/run/{run_id}` —— 同一个嵌入壳
  页面。响应时查集成（租户无关的只读取 id，因为这一请求没有身份），按 `allowed_origins`
  下发 CSP，并固定 `Cache-Control: no-store`（逐集成生成，不得被缓存共享）；集成不存在
  或已停用时仍返回页面（前端显示错误态，比空白 iframe 更有信息量），CSP 退化为
  `frame-ancestors 'none'`。

现有 5 个页面**不加** CSP / `X-Frame-Options`：它们是给内部用户直开的，动它们会改变
既有部署的行为，属于本轮不该顺手做的事（记入边界）。

## 8. 嵌入页（`apps/web/embed.html`）

- 从 `#token=` 取令牌，`?token=` 兜底；取到后**立即** `history.replaceState` 抹掉地址栏里
  的令牌，使它不留进历史记录、书签与截图（fragment 本来就不会发给服务端，也不会进 Referer）；
- 调 `GET /api/embed/{integration_id}/session`（带 `X-Embed-Token`）自举，`embed_session_invalid`
  渲染「嵌入链接无效或已过期」，网络错误单独渲染，两者不混为一谈；
- 渲染钉定 run 的阶段泳道 + 当前审核关口；**只有** scope 含 `run:review` 才渲染
  通过 / 带修改通过 / 要求修改 / 驳回四个按钮；「要求修改」「驳回」在页面层强制填说明；
  提交决策时带 `actor_user_id = 会话的 actor_id`，于是外部终端用户的审核痕迹落库可追；
- `postMessage` 与父窗口通信：`s2v.embed.ready` / `s2v.embed.resize` / `s2v.embed.navigate`。
  **目标 origin 取自 `document.referrer`**（`frame-ancestors` 已经决定了谁可以分帧，所以
  分帧方自己的 origin 是唯一值得信任的目标）；没有 referrer 时保持沉默，**绝不**广播给 `"*"`；
- 顶部显示「嵌入会话 · 剩余 N 分钟」与集成名，避免用户误以为自己在完整工作台里。

## 11. 已知的取舍与边界

- **令牌不加密**，只签名：payload 明文可读。放的都是 id，不放秘密。
- **撤销只有过期权**：无状态令牌不能单独作废，只能作废整个集成（`disabled`）或改签名密钥
  （全量失效）。要单令牌撤销就得建表 + 每请求查库，那是 V8.4 的账。
- **只允许 GET 与审核**：嵌入会话拿不到 `run:write` / `run:start`，嵌入页不能驱动 provider。
- **不做真实登录**：`sub` 是外部系统自报的终端用户 id，我们信任 `integration:manage`
  持有者代为声明身份——这与 V6.5 的「受信头」是同一个信任前提，只是收窄到一次一签。
- **不接管 provider 密钥端点**（V8.4）。
- 现有 5 个页面不受 CSP 保护，仍可被任意站点 iframe（记入边界，不在本轮扩大改动面）。
