# V7.1 HTTP API v1 实施计划

- 文档版本：v1.0
- 编写日期：2026-10-09
- 归属版本：V7 SDK 与平台嵌入版（路线图第 1 项）
- 状态：**已完成**

V7 的三件事（HTTP API v1、SDK、Webhook）里，这一件是地基：SDK 与 Webhook 都要求「同一类失败
只有一种样子、同一次重试不会产生第二个资源」。在此之前，只有三道风控闸门
（`RunGateError` / `ReviewGateError` / `PermissionDenied`）是结构化的，其余 404 / 422 / 500
还是 FastAPI 的默认输出，客户端无法用一个字段分支；写入接口也没有任何重试保护。

## 1. 目标

1. **一种失败形状。** 所有失败统一为 `{"detail": {code, message, ...details}}`，
   `code` 来自可发现的目录（`GET /api/error-codes`），`message` 面向人类、允许变化。
2. **可安全重试的写入。** 带 `Idempotency-Key` 的写请求重放返回首次结果；不带该头的请求
   **行为完全不变**（既有调用方零改动）。
3. **可发现的分页约定。** 新端点返回 `Page` 信封；既有裸数组端点保持形状不变，只补
   `limit` / `offset` 与 `X-Total-Count` 响应头。
4. **可被 SDK 生成器消费的 spec。** 文档化的失败响应就是真实返回的形状，operation 集合被
   钉住，页面路由不进入契约。

## 2. 落地范围

### 2.1 错误信封

新增 `apps/api/app/errors.py`：

- `ErrorCategory`（`request` / `identity` / `idempotency` / `gate` / `server`）。
- `ErrorCode`：**20 个**稳定错误码。`code` 是契约，`message` 不是。
- `_STATUS_CODES` / `_CATEGORY` / `_RETRYABLE` / `_DESCRIPTIONS` 四张表 +
  `_STATUS_DEFAULTS`（「只拿到状态码时该报哪个码」）。
- `ApiError(code, message, *, status_code=None, details=None)` 与 `to_payload()`。
- `error_catalog_table()` 供 `GET /api/error-codes` 发布。

`main.py` 注册全局处理器，把默认输出收进同一信封：

| 处理器 | 作用 |
|---|---|
| `ApiError` | 路由/依赖直接抛出的结构化错误 |
| `RunGateError` / `PermissionDenied` | 既有闸门，payload 已是超集，原样透传 |
| `StarletteHTTPException` | 把 `raise HTTPException(404, "x not found")` 归一化为 `not_found`；`detail` 已是带 `code` 的 dict 时不动 |
| `RequestValidationError` | 422 → `validation_error` + 字段级 `errors` |
| `IdempotentReplay` | 重放已记录的响应，附 `Idempotency-Replayed: true` |
| `Exception` | 兜底 500，不泄漏堆栈，保持信封形状 |

**状态码与错误码是「多对一」而非双射**：一个 400 可以是 `bad_request`，也可以是路由有意抛出的
`cost_budget_exceeded`。因此不变式是「状态的**回退码**必须与该状态自洽」，而不是「每个码都是
自己状态的回退码」。`validation_error` 是 422 的唯一码，不再保留语义重复的 `unprocessable`。

### 2.2 幂等键

新增表 `idempotency_keys`（migration `20261010_0013`）：`idempotency_key` / `actor_id` /
`method` / `path` / `request_fingerprint` / `state` / `status_code` / `response_body` /
`expires_at`，唯一约束 `(tenant_id, actor_id, idempotency_key)`。

`apps/api/app/idempotency.py` 用两块协作，因为只有它们各自能看到需要的时刻：

- `enforce_idempotency`（**应用级依赖**）：能安全读到已被缓冲的 body，因此能算指纹、判重放、
  占坑。挂在 `include_router(..., dependencies=[...])` 上，且在权限判定**之后**——未授权的调用
  不应该有机会占住一个 key。
- `IdempotencyRecorderMiddleware`（**中间件**）：唯一能看到**已完成响应**的位置，负责落盘或释放。
  两者通过 `scope["state"]` 通信。

判定顺序（`IdempotencyRepository.claim`）：

| 既有行状态 | 到达请求 | 结果 |
|---|---|---|
| **已过期** | 任意 body | **无条件接管**（重置为 `in_progress`，写入新指纹） |
| 未过期，指纹不同 | — | `409 idempotency_conflict` |
| 未过期，`completed`，指纹相同 | — | **重放**记录的响应 |
| 未过期，`in_progress`，指纹相同 | — | `409 idempotency_in_progress` |

**过期先于指纹**是刻意的：一条过期行只是死掉的记账数据，key 绝不能被它最初被用于什么而永久毒化。
原实现把指纹检查放在前面，导致过期且 body 不同的 key 永远返回 409；这是本次修掉的一个真实缺陷。

只有 **2xx + JSON** 响应会被记录；其余情况释放占坑，客户端可以改请求后用同一个 key 重试。

### 2.3 分页

- 新增 `Page[T]`（`items` / `total` / `limit` / `offset`，附 `has_more`），新端点一律返回它。
- 既有裸数组端点（`/api/audit-logs`）**不改 body**，改为接受 `limit` / `offset` 并回填
  `X-Total-Count`。这样 5 个已上线页面与门禁脚本零改动。
- 新增 `GET /api/idempotency-keys`（`Page` 信封）供 SDK 排查它自己重试过什么。

### 2.4 OpenAPI

- `info.version` 跟随路线图（V0–V6 完成 → `0.8`）。
- **不改 URL 前缀**：重命名为 `/api/v1` 会打挂全部既有调用方与 5 个页面，收益不抵风险，
  版本改用 `info.version` 表达。
- 通过 `include_router(..., responses={...})` 为**每个** operation 声明 400/403/404/409/422/500
  的响应模型为 `ErrorEnvelope`。这不只是装饰：不声明时 schema 会宣称 422 返回 FastAPI 的
  `HTTPValidationError`，而实际返回的是本次的信封——按 spec 生成的 SDK 会解析错误的形状。
- 五个 HTML 页面设 `include_in_schema=False`（它们返回 HTML，不是 JSON）。副产品是 spec 与
  权限表**精确对齐**：`POLICY` ∪ `OPEN_ENDPOINTS` == 全部文档化 operation。

### 2.5 未受控端点

`/api/error-codes` 登记进 `OPEN_ENDPOINTS`（静态参考数据，不含租户数据），
`/api/idempotency-keys` 登记进 `POLICY`（租户级，`member:read`）。

## 3. 验证

- `tests/test_api_contract.py`（26 项）：目录自洽、信封在 404/422/闸门/权限四条来源上一致、
  幂等重放与冲突、按 actor 隔离、**过期接管**、失败释放占坑、超长 key、`Page` 与
  `X-Total-Count`。
- `tests/test_openapi_contract.py`（9 项）：operation 集合钉住（96 path / 117 operation）、
  spec 与权限表精确划分、页面不入契约、**每个 4xx/5xx 都声明 `ErrorEnvelope` 且
  `HTTPValidationError` 不再出现**、operationId 唯一、分页参数齐备、模板不含具体 id。
- 部署门禁新增第 15 节（23 项），含真实 HTTP 上的重放/冲突/405/超长 key/`X-Total-Count`。
- migration `20261010_0013` 做 upgrade → downgrade → upgrade 往返（27 → 26 → 27 张表）。

## 4. 明确不做的事

- **不做 V7 的 `api_keys` / scopes**：那是面向 SDK 的编程访问凭证，与「重试安全」是两件事，
  留待 V7.2 与 SDK 一起设计。
- **不改 URL 前缀**，不引入 `/v1`。
- **不把既有裸数组端点改成 `Page`**：会让已上线的 5 个页面与门禁脚本同时失配。
- **不重写所有 `HTTPException` 的文案**：采用「按状态映射默认 code」的保守做法，只统一形状，
  不逐条改写业务文案。
- **不做限流**：`rate_limited` 码先定义、目录可见，但限流实现属 V8。
- 不做 Webhook 与 SDK 本身（V7.2 / V7.3）。
