## 1. 为什么有这一版

V1.0 收口时留下的「还剩什么」（`docs/FULL_VERSION_ROADMAP.md` §2.2 与 §2.1 的遗留列）分成三类，
用户在本轮明确处置了前两类：

- **Provider 生态广度 —— 不扩展。** 只保留 `tool_kit` 的 adapter 合同与 selector/fallback 机制，
  后续按需再加 provider。这是差异表里最大的一条遗留，但它的成本主要在**对接与运维**而不是架构；
  留成「有合同、没实现」比一次接五家更诚实。
- **其余四条 —— 补齐。** 媒体分析高级项、V3 遗留的两条 pipeline、V7.1 遗留的列表排序、
  §1 边界的真实登录与租户隔离收敛。

这四条的共同属性是：**判据已经写在文档里，只是没实现**。它们不是新方向，是把已经承诺过的缺口
填平，所以合并成一个里程碑，一次把「文档说要做、代码没做」的清零。

**明确不做（写下来，免得下一个人以为漏了）**：

- **不做子域名 / 路径前缀租户路由。** 用户在两种方案里选了「只做租户隔离，不做路由」。

## 3. 设计决策

### 3.1 版本号 1.1.0，且必须是「纯增量」

`docs/API_STABILITY.md` 自 `1.0.0` 生效。本项新增的每个面都必须是**可选、可忽略**的：

- 新增分析字段 → 走 artifact schema 的**向后兼容新版本**（`v1` 语义不动，新字段只增不改）。
- 新增排序参数 → 不传就是原有顺序，既有客户端零改动。
- 新增登录 → **不改变**无凭证请求的行为（与 V7.2 引入 API key 同一策略：没有 `Authorization`
  头的请求完全不受影响）。
- 租户隔离收敛 → 把原本「查得到全部」收成「只查得到自己的」。**单租户部署行为完全一致**，
  多租户上是修复越权。**如实记进 CHANGELOG**：这是本次唯一的语义收紧，按「收窄 = 破坏性变更」
  的既定判据处理。

### 3.2 身份解析的优先级是**追加**，不是重排

现有顺序（`apps/api/app/actor.py::resolve_actor`）：API key → 受信头 → 默认身份。
新增会话后：**API key → 会话 → 受信头 → 默认身份**。

会话插在受信头**之前**、API key **之后**：

- 在受信头之前：一条真实凭证比网关转发的隐式身份更可信，与 V7.2「Bearer 优先于 `X-Actor-Id`」同一条判断。
- 在 API key 之后：机器凭证比人类会话更专用，且同时持有两者的客户端应当以显式出示的那一个为准
  ——反过来会让「用 API key 调、但会话还开着」的行为不可预测。

### 3.3 会话**落表**，与 V7.4 的嵌入令牌刻意相反

`docs/PLATFORM_PLAN.md` §1 为嵌入会话写过「不落表」的理由。**登录会话走反例，理由也写在那句话里**：

- 嵌入令牌的生命周期由**伙伴平台**控制（停用集成即撤销），平台不需要逐令牌吊销列表。
- 登录会话的撤销点是**用户自己**（登出、改密码、管理员踢人），这些是**高频、单条、必须立即生效**
  的操作。无状态令牌要达到同样效果只能轮换全局密钥——那会把一次登出变成全员失效。

所以引入 `user_sessions` 表：一行一个会话，`revoked_at` 为软撤销，**只存令牌哈希**（同 API key
的处理，不存明文）。

### 3.4 租户隔离用「不过滤就是泄露」的默认值

收敛的做法不是给每个查询加 `WHERE tenant_id = ?`（漏一处就有一个越权口子），而是把租户作为
**默认参与条件**：仓储层的查询构造统一经过一个入口，调用方要跨租户必须**显式**说出理由
（目前只有平台级的部署姿态与错误码目录需要，它们本来就不含租户数据）。

## 4. 逐项验收标准

### T93 媒体分析高级项

- `packages/media_analysis_kit` 新增三类真实分析能力，**每类都有本地降级路径**：
  - **镜头边界**：FFmpeg 场景变化检测（`select='gt(scene,T)'` + `showinfo` 解析），产出
    `[{index, start_seconds, end_seconds, duration_seconds, confidence}]`；无视频流 → 空列表 + warning。
  - **音频能量**：FFmpeg `astats` / `ebur128` 分段响度时间线，产出归一化采样点与
    「静音段 / 高能量段」摘要；无音频流 → 空 + warning。
  - **ASR 转写**：走**已接入的 provider**，并保留 `local` 降级（退化成占位转写，并在 artifact 里
    如实标注 `engine` 与 `limitations`）。没有 provider key 时**不得伪造成「转写成功」**。
- 三类结果写进既有 `media_analysis_report.v1`（`scenes` / `media_summary.audio` / `transcript`），
  **不改 v1 语义**，只填补此前一直为空的字段。
- 测试覆盖有流 / 无流 / 命令失败三条分支，且**不依赖真实 ffmpeg 二进制**（注入假 runner）。

### T95 列表排序（✅ 已完成）

- 受控排序：端点声明**允许排序的字段白名单**与默认排序；未知字段 → 422（走既有校验错误码）。
- 稳定排序：允许多字段，且**末尾隐式追加主键**，否则同值行的相对顺序在不同页之间不稳定
  （分页 + 非唯一排序键 = 会漏行 / 重行）。
- 不传排序参数时**字节级等同于改动前**。
- **落地**：`apps/api/app/sorting.py` 的 `SortSpec` 集中声明六端点契约（含 `pk_desc` 对齐
  各端点旧默认的主键方向，显式传默认串与不传参数连并列顺序都一致）；仓储层 `_sorted()` 单点收口，
  `sort=None` 时保持原 `order_by`。覆盖 `/api/audit-logs` / `/api/idempotency-keys` / `/api/api-keys`
  / `/api/webhooks` / `/api/webhooks/{id}/deliveries` / `/api/external-integrations`。
- **明确排除**：`GET /api/projects/{id}/runs`（内存仪表盘投影、仅 limit 无 offset，排序收益为负）；
  `GET /api/runs/{id}/events`（事件流按 `sequence` 递增是消费者游标语义，任何其它排序都会破坏续读）。

### T96 真实登录（✅ 已完成）

- `users` 表新增可选 `password_hash` / `password_updated_at`（`status` 列本来就有）；新表 `user_sessions`
  （migration `20261012_0022`，全库 35 → **36** 张表，upgrade→downgrade→upgrade 往返已验）。
- 端点：`POST /api/auth/login`（开放，登录即身份自举）、`POST /api/auth/logout`（幂等吊销）、
  `GET /api/auth/session`（自省），外加 `POST /api/users/{user_id}/password`（受控
  `member:manage` 租户级；设新密码立即杀死该用户既有会话）。
- 密码哈希用**标准库**（`hashlib.scrypt`，逐哈希随机盐、成本参数内嵌），不引入新依赖；
  会话令牌 `Bearer s2v_sess_...` 只存前缀 + 加 pepper 摘要（同 API key 的存储拆分），
  TTL 默认 72h（`SESSION_TTL_HOURS`）。
- **默认身份路径零改动**：`DEFAULT_ACTOR_ID` 回退、受信头、API key、嵌入令牌全部保持原语义，
  由既有测试与门禁证明；优先级 API key → 登录会话 → 受信头 → 默认。
